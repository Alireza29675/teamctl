# Agent workspace and interface instances

Accepted2026-10-18 for the workspace branch. Supersedes the public manager/worker split and manager-only human routing.

Agents are a single map. Hierarchy (`reports_to`) is optional descriptive topology; direct-message and channel ACLs control collaboration. A named interface instance has a provider, stable ID, name, description, capabilities and agent grants. Two Telegram bots are distinct instances. Web is automatic. Received messages persist full source metadata; changing a label later must not rewrite history. Replies inherit the source conversation unless explicitly routed to another granted instance. Grants are checked when sending and again when claiming delayed delivery.

SQLite remains the durable mailbox and human transcript authority. The web server embeds static assets in the Rust binary and uses authenticated same-origin JSON APIs. Browser authority is an ephemeral capability passed in the URL fragment, removed immediately, then sent in Authorization headers. Host/Origin checks and no cross-origin access protect the local control surface. Interactive HTML is an opaque-origin sandbox with no parent API, external requests or navigation privileges. Files are private cached snapshots with bounded reads, allow-root/scanner enforcement for agent-origin files and configurable expiry, default30days.

Native workers run one provider turn at a time, keep exact provider session IDs and durable wake checkpoints, and release the model process when idle. CLI print/JSON transports are the initial backend; Codex app-server and OpenCode long-lived HTTP transports remain extension seams if streaming/control needs justify their process overhead. tmux is retained for explicitly interactive execution. Host processes and intentionally shared container coordination data belong to a trusted local operator boundary; interface grants are routing permissions, not a multi-tenant OS security boundary. See the native guide for explicit sandbox mounts/authentication and limitations.

Verification targets disposable fake runtimes, durable message retries, capability revocation, sandbox policy, real browser actions and bounded opt-in provider calls. Detailed planning, critique, research and chronological evidence are maintained in Sooleh task memory, outside the product repository. No deployment or main integration follows automatically from local verification.
